# ado-dash Domain Context

A terminal dashboard for Azure DevOps. This glossary pins the canonical term for every concept that appears in the codebase, config, and docs. When a term here conflicts with an ADO API field name or a Go type name, this file wins for human communication — code may differ where the external API forces it.

---

## Identity & Auth

**Organization**
The Azure DevOps tenant, identified by a URL (`dev.azure.com/{org}` or `{org}.visualstudio.com`). The top-level scope for all API calls.
_Avoid_: tenant, account, instance

**Project**
A workspace within an Organization, grouping repositories, work items, and pipelines. Selected at startup via the Project Picker.
_Avoid_: workspace, namespace, repo-group

**Profile**
A named pairing of an Organization URL and an Auth Provider, stored in `config.yml`. Multiple profiles enable switching between orgs or identities.
_Avoid_: account, identity, user, context

**Auth Provider**
One of three pluggable authentication strategies: Azure CLI, PAT, or Service Principal. Selected during the first-run wizard and stored per Profile.
_Avoid_: auth method, credential type, login method

**PAT (Personal Access Token)**
An ADO bearer token generated by the user. ado-dash stores the *name of the environment variable* holding the token — never the token value itself. See also: Env Var Reference.
_Avoid_: token, secret, API key

**Env Var Reference**
The *name* of an environment variable holding a secret (e.g. `"AZURE_DEVOPS_PAT"`). ado-dash reads the referenced env var at runtime. Raw token values entered directly are rejected.
_Avoid_: secret reference, token reference, env var

**Service Principal**
An OAuth client-credentials identity for CI or scripted access. Uses `clientId` + `tenantId` in config and a client secret via an Env Var Reference.
_Avoid_: service account, app identity, managed identity

## Azure DevOps Entities

**Pull Request**
An ADO Git pull request. Canonical abbreviation in code and UI: "PR". Fetched from the Git PR API (`/_apis/git/repositories/{id}/pullrequests`).
_Avoid_: merge request, change request

**Vote**
A reviewer's integer response on a PR: `10` = Approve, `5` = Approve with Suggestions, `0` = No vote, `−5` = Wait for Author, `−10` = Reject. The raw integer is the source of truth; display labels are derived.
_Avoid_: review, approval, reaction, review status

**Policy Evaluation**
The result of an ADO branch policy check applied to a PR (e.g. minimum reviewer count, required build passing, comment resolution). Fetched separately from the policy evaluations API.
_Avoid_: check, gate, CI status, policy check

**Work Item**
An ADO tracking unit. Concrete types — Bug, Task, User Story, Feature, Epic — are process-template-specific and not hardcoded in ado-dash logic.
_Avoid_: ticket, issue, card, task (as a generic)

**WIQL**
Work Item Query Language. The SQL-like query syntax used to define the server-side filter for a work item Sub-tab. User-authored in `config.yml`.
_Avoid_: query, filter, WI query

**Iteration**
A sprint in ADO terms. Identified by an Iteration Path string resolved at runtime. ado-dash never uses the bare `@CurrentIteration` WIQL macro; it resolves the Iteration Path explicitly.
_Avoid_: sprint (in code — use Iteration), cycle

**Iteration Path**
The fully qualified string identifying an Iteration, e.g. `"MyProject\\Sprint 12"`. Resolved at runtime via the Team Iterations API and substituted into WIQL before sending.
_Avoid_: sprint path, sprint name, iteration name

**Team**
An ADO team within a Project. Required to resolve the current Iteration Path. Auto-detected on first use; saved to the State File.
_Avoid_: group, squad, team context

**Pipeline**
An ADO Build pipeline (YAML or Classic). The primary list source is the Build API (`/_apis/build/builds`), not the Pipelines Runs API.
_Avoid_: workflow, build definition, CI pipeline (as a type name)

**Build**
A single run of a Pipeline. Has two orthogonal status fields: `statusFilter` (e.g. `inProgress`, `completed`) and `resultFilter` (e.g. `succeeded`, `failed`).
_Avoid_: run, job, workflow run, pipeline run (as a type name)

**Release**
An ADO Classic Release, managed via the vsrm subdomain (`vsrm.dev.azure.com/{org}`). Distinct from a Build; uses a separate base URL that the ADO Client must track explicitly.
_Avoid_: deployment, build release, CD run

**Approval**
A pending gate on a Release requiring a human to approve or reject before the release proceeds.
_Avoid_: gate, review, release review

## UI

**Screen**
A full-terminal view managed by the Screen Stack. The five named screens are: Auth Wizard, Project Picker, Main Dashboard, Detail View, and Settings. Account Switcher is a sixth screen pushed from Main Dashboard.
_Avoid_: page, view, panel, route

**Screen Stack**
The navigation model. Screens are pushed on top of or popped off a stack; there is no linear routing. Pressing `b`/`esc` pops the current screen.
_Avoid_: router, navigation stack, page stack, history

**Overlay**
A transient UI state that appears on top of the current Screen without replacing it: loading spinner, error state, help overlay, search input, confirmation prompt. Overlays are not Screens.
_Avoid_: modal (reserve this for the confirmation prompt specifically), popup, sheet

**Section**
One of the four fixed sidebar entries: PRs, Work Items, Pipelines, Releases. A Section contains one or more Sub-tabs.
_Avoid_: category, module, panel, area

**Sub-tab**
A single user-configured query within a Section, rendered as a named tab in the tab bar. Each Sub-tab maps to one set of API parameters or a WIQL string.
_Avoid_: tab (when meaning a configured query), filter, view

**Preview Pane**
The right-side panel on the Main Dashboard showing a summary of the selected list item. Width is user-adjustable and persisted to the State File.
_Avoid_: detail pane, info pane, aside, sidebar (the left strip is the Sidebar)

**Sidebar**
The fixed left navigation strip showing the four Sections with active indicators and notification badges.
_Avoid_: nav, navigation panel, left panel

**Zen Mode**
A display mode hiding the header bar, Sidebar, and footer, leaving only the tab bar and content area. Toggled with `Z`.
_Avoid_: focus mode, full screen, distraction-free

**Theme**
A named set of Color Slot → hex assignments. All Lip Gloss styles reference Color Slots; no component code contains raw hex values.
_Avoid_: color scheme, skin, palette

**Color Slot**
A semantic role in the `Theme` struct — e.g. `Surface`, `Accent`, `Badge` — that maps to a hex value per Theme. Slots are the stable names; hex values vary per Theme.
_Avoid_: CSS variable, token, color variable

## Config & State

**Config File**
`~/.config/ado-dash/config.yml` (or `.ado-dash.yml` in CWD). User-authored. Never auto-rewritten after the first-run wizard creates it.
_Avoid_: settings file, preferences file, dotfile

**State File**
`~/.config/ado-dash/state.json`. Auto-written by the TUI for runtime state (active profile, selected project, UI widths). Never hand-edited by users.
_Avoid_: cache, database, session file

## Data Fetching

**Fan-out**
The pattern of issuing the same query to multiple repositories in parallel, then merging results sorted by `updatedAt` descending. Used when a Sub-tab specifies more than one repository.
_Avoid_: parallel fetch, scatter-gather, multi-repo query

**Continuation Token**
The pagination cursor used by the Build API and Release API, returned as the `x-ms-continuationtoken` response header. The Git PR API uses `$skip` instead — these are different mechanisms.
_Avoid_: cursor, page token, next token

**Client-side Filter**
A filter applied in ado-dash after data is fetched from ADO, because the ADO API does not expose the filter as a server parameter. Examples: `draft: true`, `filter: noVote`. Pages are fetched until `limit` matching items are collected, up to `maxFetchPages`.
_Avoid_: post-filter, local filter, in-memory filter
